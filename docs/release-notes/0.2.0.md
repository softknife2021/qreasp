# qreasp 0.2.0

A reliability release. It fixes 19 bugs found in a full code review, three more found while fixing
them, and makes the WebDriver module do what its API always promised. **It requires Java 21.**

## Install

qreasp is published to GitHub Packages. GitHub requires a token with `read:packages` even for public
packages; put it in `~/.gradle/gradle.properties` as `gpr.user` / `gpr.key`.

```groovy
repositories {
    mavenCentral()
    maven {
        url = uri('https://maven.pkg.github.com/softknife2021/qreasp')
        credentials {
            username = findProperty('gpr.user') ?: System.getenv('GITHUB_ACTOR')
            password = findProperty('gpr.key') ?: System.getenv('GITHUB_TOKEN')
        }
    }
}

dependencies {
    testImplementation 'com.softknife:qreasp:0.2.0'
}
```

## Before you upgrade

- **The package and group are now `com.softknife`** (they were `com.restbusters`). Change the
  dependency to `com.softknife:qreasp:0.2.0` and replace `import com.restbusters.` with
  `import com.softknife.` in your code. Class names are unchanged.
- **Java 21 is required.** Projects on Java 17 should stay on 0.1.8.
- **Bring your own logging backend and TestNG.** Logback, TestNG and MockWebServer are no longer pulled
  in by qreasp.
- **A request that gets no response is now `FAILED`**, not `SKIPPED`.
- **`DriverManager` no longer sets a 10-second implicit wait.** Actions wait explicitly with their own
  timeout. If your own code drives the raw `WebDriver`, add explicit waits there.
- **Some calls now refuse bad input** with an `IllegalArgumentException` that names the problem, where
  they used to fail later or silently: unknown browser names, blank template name or version, invalid
  JSON in either side of a patch, missing classpath resources, malformed URLs.
- **Removed:** `RestClientHelper.addHeader`, `addHeaders`, `removeHeader` (they did nothing), and
  `TemplateTransform.main`.
- **`TCBuildExecutor` now reports FAILURE** for builds that were never triggered or were still running
  when the wait ran out. These used to be reported as SUCCESS.

## What's fixed

**Security**
- Basic and Bearer credentials, cookies and token-like headers and query parameters were written to the
  log on every request. They are now logged as `***`.

**HTTP client**
- Clients created with default headers were deleting the request's own headers, including
  `Content-Type`.
- `HEAD` and `OPTIONS` requests were sent as `GET`.
- A request with a non-JSON body (form data, XML, text) failed before it was sent.
- `Content-Type` could be sent twice.

**WebDriver**
- The retry strategy, timeout and polling interval were accepted and then ignored. They now apply.
  A step missing a required input is not retried.
- 23 of the 47 action types threw "not implemented". All are implemented now, and `BrowserContext` has
  new methods for frames, windows, drag and drop, scrolling, JavaScript, file upload, waits and
  validations.
- A state built with `WebDriverState.withLocator` was rejected by the executor.

**Integrations**
- An OpenAPI path with an unclosed `{` hung the JVM.
- `OpenApiV3Manager.getSwaggerApiResources` always returned an empty list.
- Stash v2 calls sent `{workSpace}` in the URL literally, and one call's paging leaked into the next.

**Utilities**
- `PerformanceTestUtil` reported timed-out runs as complete. It now reports them as
  `truncated: true`, and it no longer crashes when the delay range is zero.
- Encoded `%7Bname%7D` placeholders were never substituted.
- `Context` was documented as thread-safe but was not.
- Singletons ignored new configuration after the first call.
- Several resource and thread leaks.

## Also new

- SpotBugs static analysis runs on every build and fails the build on a new finding.
- Test tasks: `test` needs no browser and no internet, and `networkTest` and `browserTest` hold the
  tests that do. Every test has a default timeout, so a hung browser can no longer hold the build.
- CI on every push and pull request. Publishing runs from a version tag.

## Verified

- **Unit tests:** 348 passed, 0 failed, on Java 21.
- **Network tests:** 18 passed, 0 failed.
- **SpotBugs:** 0 findings.
- **Browser tests:** 19 passed against headless Chrome, including navigation, click, typing, submit,
  select and screenshots.

## Known issues

- One browser test (`testSelectByValue`) depends on w3schools.com, whose page load can hang. Before
  this release that hang stopped the whole build. Now it fails after two minutes, but the stuck Chrome
  session can still take later browser tests down with it.
- `JiraHelper.searchJiraWithJQL` was not re-verified against Jira Cloud, where Atlassian retired the
  old search endpoint in 2025.
